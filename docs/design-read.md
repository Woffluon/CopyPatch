# Documentation design read

**Product character:** a midnight developer tool for a security-sensitive embedded runtime.

**Design direction:** ENERGY 1 / RHYTHM 2 / MOTION 1.

The documentation should help a React developer choose a viable host path, understand the same-origin boundary, and verify an integration without marketing friction. The site keeps its dark technical surface, compact typography, restrained borders, and the existing CopyPatch banner and logo. Accent color is reserved for the active route, search focus, and the primary decision points.

The page hierarchy follows the reader's task: choose a framework, understand the request and data flow, learn shared editing and publishing concepts, then move to operations and source-verified API reference. Motion remains limited to native focus and menu states. Diagrams have text equivalents, and every interactive control has a visible focus state and keyboard path.

Avoid decorative imagery, gradients, dashboards, fabricated product screenshots, and generic marketing claims. Existing product assets are used where they establish identity, not as filler.
