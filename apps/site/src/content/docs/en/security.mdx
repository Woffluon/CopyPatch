<h1>Security Architecture & Threat Model</h1>
  <p class="lead">
    Security is a foundational design pillar of CopyPatch. Unlike traditional CMS platforms that store arbitrary HTML and expose wide attack surfaces, CopyPatch enforces strict architectural boundaries to eliminate stored XSS, prevent brute-force attacks, and isolate editing sessions.
  </p>

  <h2>1. Strict Plain-Text Invariant (Zero XSS)</h2>
  <p>
    CopyPatch accepts, validates, and stores <strong>plain-text strings only</strong>:
  </p>
  <ul>
    <li>HTML tags (e.g. <code>&lt;script&gt;</code>, <code>&lt;iframe&gt;</code>, <code>&lt;img onerror&gt;</code>) are never parsed or executed as active DOM nodes.</li>
    <li>React's standard text interpolation safely renders all copy as text nodes (0% <code>dangerouslySetInnerHTML</code>).</li>
    <li>Server-side validators normalize text. The default maximum value length is 10,000 characters and configuration can raise it to 100,000 characters.</li>
  </ul>

  <h2>2. Same-Origin Boundary & Origin Validation</h2>
  <p>
    CopyPatch v3 runs exclusively inside the host application's origin:
  </p>
  <ul>
    <li>The embedded API rejects any mutating request whose <code>Origin</code> header does not exactly match the host domain.</li>
    <li>CopyPatch does not emit CORS allowlist headers or support insecure cross-origin proxy setups.</li>
  </ul>

  <h2>3. Argon2id Cryptographic Parameters</h2>
  <p>
    The built-in passphrase strategy uses <strong>Argon2id</strong> (RFC 9106 standard) to resist GPU, ASIC, and side-channel brute-force attacks:
  </p>
  <table>
    <thead>
      <tr>
        <th>Parameter</th>
        <th>Value</th>
        <th>Rationale</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><strong>Algorithm</strong></td>
        <td><code>Argon2id</code></td>
        <td>Hybrid defense against both side-channel and GPU-accelerated brute-force attacks.</td>
      </tr>
      <tr>
        <td><strong>Memory Cost (m)</strong></td>
        <td><code>19 MiB (19456 KiB)</code></td>
        <td>Forces high dedicated RAM allocation per candidate guess on attack hardware.</td>
      </tr>
      <tr>
        <td><strong>Time Cost (t)</strong></td>
        <td><code>2 iterations</code></td>
        <td>Delivers robust computational workload without introducing perceivable login latency.</td>
      </tr>
      <tr>
        <td><strong>Parallelism (p)</strong></td>
        <td><code>1 lane</code></td>
        <td>Ensures deterministic, predictable execution across single-core cloud environments.</td>
      </tr>
      <tr>
        <td><strong>Salt Length</strong></td>
        <td><code>32 bytes (256-bit)</code></td>
        <td>Cryptographically random salt generated via <code>node:crypto</code> for every hash.</td>
      </tr>
    </tbody>
  </table>

  <h2>4. Hardened Session & Token Handling</h2>
  <ul>
    <li><strong>High-Entropy Tokens:</strong> Session tokens are generated with 256-bit cryptographic entropy (<code>crypto.randomBytes(32)</code>).</li>
    <li><strong>Token Hashing at Rest:</strong> Storage adapters only receive and persist SHA-256 hashes of session and rate-limit identifiers. Even if a raw database file is exposed, session tokens cannot be recovered.</li>
    <li><strong>Secure Cookies:</strong> Transmitted with <code>HttpOnly</code>, <code>SameSite=Strict</code>, and <code>Secure</code> flags. Over HTTPS, the <code>__Host-</code> prefix is enforced to prevent subdomain injection.</li>
  </ul>

  <h2>5. Dual-Token CSRF Protection</h2>
  <p>
    All state-changing endpoints (<code>POST</code>, <code>PUT</code>, <code>DELETE</code>) require two independent verification factors:
  </p>
  <ol>
    <li>The browser's automated <code>HttpOnly</code> session cookie.</li>
    <li>A unique CSRF token stored in JavaScript memory and passed via the custom <code>x-copypatch-csrf</code> header.</li>
  </ol>

  <h2>Threat Analysis Matrix</h2>
  <table>
    <thead>
      <tr>
        <th>Threat Vector</th>
        <th>Severity</th>
        <th>CopyPatch Architectural Defense</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><strong>Stored XSS</strong></td>
        <td>Critical</td>
        <td>Strict plain-text normalizers; standard React text node interpolation; zero HTML execution.</td>
      </tr>
      <tr>
        <td><strong>CSRF Attacks</strong></td>
        <td>High</td>
        <td>Exact same-origin checking + <code>SameSite=Strict</code> cookies + required <code>x-copypatch-csrf</code> header.</td>
      </tr>
      <tr>
        <td><strong>Brute-Force Login</strong></td>
        <td>High</td>
        <td>Persistent IP/key rate limiting + 19 MiB Argon2id memory hardness.</td>
      </tr>
      <tr>
        <td><strong>SQL Injection</strong></td>
        <td>Critical</td>
        <td>100% parameterized queries in <code>better-sqlite3</code> and <code>pg</code>; strict alphanumeric key regex validation.</td>
      </tr>
      <tr>
        <td><strong>Session Disclosure</strong></td>
        <td>High</td>
        <td>SHA-256 token hashing in storage; <code>HttpOnly</code> + <code>Secure</code> + <code>__Host-</code> prefixes.</td>
      </tr>
      <tr>
        <td><strong>Revision Overwrites</strong></td>
        <td>Medium</td>
        <td>Atomic compare-and-swap (CAS) validation on draft and published revision counters.</td>
      </tr>
    </tbody>
  </table>
